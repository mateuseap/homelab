# 9Router on homelab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy 9Router (self-hosted AI gateway, `decolua/9router`) onto the homelab k3s cluster as a new GitOps-managed app, reachable at `https://9router.lab.mateuseap.com`, so the user's local Claude Code CLI can point at it for rate-limit fallback.

**Architecture:** Single Deployment + PVC (SQLite state) + Service + Ingress in a new `9router` namespace, plus an ArgoCD Application manifest: the exact shape `apps/mixtape/` already uses in this repo. No new platform components; rides on existing Traefik/cert-manager/sealed-secrets/ArgoCD.

**Tech Stack:** Kubernetes manifests (YAML), k3s, ArgoCD, cert-manager, sealed-secrets, Traefik. Image: `decolua/9router:latest` (Docker Hub, third-party).

## Global Constraints

- Node is 1 vCPU / 4 GB total. Every container gets explicit `resources.requests`/`limits` (from spec, "Deployment" section).
- No plaintext secrets in git, ever, only `SealedSecret` output (repo-wide rule, `CONTRIBUTING.md`).
- English only, no em dash characters in docs or manifests (`CONTRIBUTING.md`, "Golden rules").
- Branch from `develop`, PR into `develop`, Conventional Commits (`feat:`, `docs:`, etc.) (`CONTRIBUTING.md`, "Workflow").
- `REQUIRE_API_KEY=true`, `AUTH_COOKIE_SECURE=true`, `ENABLE_REQUEST_LOGS=false`, no Cloud Sync opt-in (spec, "Scope decisions" + "Security note").
- This sandbox has no `kubectl` or `kubeseal` installed and no cluster credentials. Any step below that needs them is marked **MANUAL (user)** (the plan gives the exact command, but it must be run by the user in an environment with cluster access, not fabricated as passing here).

### Task 3: Secrets template

- [ ] **Step 1: Write the template**

```yaml

# Lives in docs/ (NOT apps/) because ArgoCD applies every YAML under apps/, so
# a template there would be deployed literally and fight the sealed secret.
#

#        jwt-secret:       openssl rand -base64 48 | tr -d '\n'

#        < /tmp/secrets.yaml > apps/9router/sealed-secrets.yaml

#   5. shred -u /tmp/secrets.yaml

kind: Secret
metadata:
  name: 9router-secrets
  namespace: 9router

  machine-id-salt: CHANGE-ME
```

### Task 5: Ingress manifest

**Files:**
- Create: `apps/9router/ingress.yaml`

**Interfaces:**
- Consumes: Service `9router` port `80` (Task 4).
- Produces: public route at `9router.lab.mateuseap.com`, TLS secret name `9router-tls` (cert-manager creates this automatically on first request, no task creates it directly).

- [ ] **Step 1: Write the manifest**

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: 9router
  namespace: 9router
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
spec:
  ingressClassName: traefik
  rules:
    - host: 9router.lab.mateuseap.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: 9router
                port: { number: 80 }
  tls:
    - hosts: [9router.lab.mateuseap.com]
      secretName: 9router-tls
```

### Task 6: Deployment + PVC manifest

**Files:**
- Create: `apps/9router/deployment.yaml`

**Interfaces:**
- Consumes: Secret `9router-secrets` keys `jwt-secret`, `initial-password`, `api-key-secret`, `machine-id-salt` (Task 3 defines the template; the real Secret exists only after Task 8's manual sealing step). Service selector `app: 9router` (Task 4).
- Produces: Deployment `9router` and PVC `9router-data` (5Gi, `local-path`) in namespace `9router`, container port `20128`.

- [ ] **Step 1: Write the manifest**

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: 9router
  namespace: 9router
spec:
  replicas: 1
  strategy: { type: Recreate }
  selector:
    matchLabels: { app: 9router }
  template:
    metadata:
      labels: { app: 9router }
    spec:
      securityContext:
        seccompProfile: { type: RuntimeDefault }
      containers:
        - name: 9router
          # Third-party image on Docker Hub, not built by this user's own
          # CI, so it does not follow the ghcr.io/mateuseap/<name>:latest
          # convention the other apps use. No upstream :sha tag exists.
          image: decolua/9router:latest
          imagePullPolicy: Always
          securityContext:
            allowPrivilegeEscalation: false
            capabilities: { drop: [ALL] }
          ports: [{ containerPort: 20128 }]
          env:
            - name: NODE_ENV
              value: production
            - name: DATA_DIR
              value: /data
            - name: PORT
              value: "20128"
            - name: REQUIRE_API_KEY
              value: "true"
            - name: AUTH_COOKIE_SECURE
              value: "true"
            - name: ENABLE_REQUEST_LOGS
              value: "false"
            - name: JWT_SECRET
              valueFrom:
                secretKeyRef: { name: 9router-secrets, key: jwt-secret }
            - name: INITIAL_PASSWORD
              valueFrom:
                secretKeyRef: { name: 9router-secrets, key: initial-password }
            - name: API_KEY_SECRET
              valueFrom:
                secretKeyRef: { name: 9router-secrets, key: api-key-secret }
            - name: MACHINE_ID_SALT
              valueFrom:
                secretKeyRef: { name: 9router-secrets, key: machine-id-salt }
          resources:
            requests: { cpu: 30m, memory: 100Mi }
            limits: { memory: 250Mi }
          readinessProbe:
            tcpSocket: { port: 20128 }
            initialDelaySeconds: 5
          volumeMounts:
            - name: data
              mountPath: /data
      volumes:
        - name: data
          persistentVolumeClaim: { claimName: 9router-data }
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: 9router-data
  namespace: 9router
spec:
  accessModes: [ReadWriteOnce]
  storageClassName: local-path
  resources:
    requests: { storage: 5Gi }
```
